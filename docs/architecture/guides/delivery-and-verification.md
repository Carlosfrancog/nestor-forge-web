# Entrega, ferramentas e verificação

Este guia descreve a cadeia de build e os pontos de verificação disponíveis no repositório. Os comandos abaixo são os declarados pelo projeto; a presença de um teste não significa que ele tenha sido executado nesta revisão.

| --- | --- | --- |

O diretório `examples/` contém entradas exemplares, inclusive as três especificações de agentes de contexto; não é um módulo de execução. O pacote de contexto é uma entrega derivada dessas entradas. **Inferência:** alterações nas especificações de contexto precisam ser acompanhadas de nova inspeção do ZIP gerado, pois a geração passa por mais de um adaptador ([`scripts/build_context_agents.py:43`](../../../scripts/build_context_agents.py#L43), [`scripts/build_context_agents.py:71`](../../../scripts/build_context_agents.py#L71)).

## Publicação declarada

O workflow de GitHub Pages dispara em `push` para `main` ou manualmente. Ele instala dependências Node, executa verificações da extensão, empacota o VSIX, monta o site, executa `test_forge.py` e publica `dist/site` ([`.github/workflows/pages.yml:3`](../../../.github/workflows/pages.yml#L3), [`.github/workflows/pages.yml:28`](../../../.github/workflows/pages.yml#L28), [`.github/workflows/pages.yml:38`](../../../.github/workflows/pages.yml#L38), [`.github/workflows/pages.yml:42`](../../../.github/workflows/pages.yml#L42)). A página carrega `site/app.js`, que envia a especificação ao worker para compilar um ZIP no navegador ([`site/index.html:12`](../../../site/index.html#L12), [`site/app.js:316`](../../../site/app.js#L316)).

**Não verificado:** o resultado de uma execução recente do workflow, o download público do VSIX e a instalação do pacote publicado. O workflow mostra o caminho configurado, não o estado de produção.

## Ferramentas de manutenção fora do runtime

`scripts/commit_ast.py` inspeciona alterações Git com resumo de funções, métodos e classes Python por AST e metadados para outros arquivos ([`scripts/commit_ast.py:104`](../../../scripts/commit_ast.py#L104), [`scripts/commit_ast.py:140`](../../../scripts/commit_ast.py#L140)). Seu comando `commit` exige caminhos explícitos, recusa alterações já staged, verifica alertas de privacidade e informa os caminhos efetivamente incluídos ([`scripts/commit_ast.py:161`](../../../scripts/commit_ast.py#L161), [`scripts/commit_ast.py:216`](../../../scripts/commit_ast.py#L216), [`scripts/commit_ast.py:240`](../../../scripts/commit_ast.py#L240)). É uma ferramenta de desenvolvimento; nenhum dos pontos de entrada de geração de agente ou mapeamento depende dela.

O analisador de diff da extensão é outra ferramenta: `vscode-extension/scripts/diff-ast.js` chama `src/diffAst.js`, que lê mudanças Git e as analisa com `src/structural.js` ([`vscode-extension/scripts/diff-ast.js:5`](../../../vscode-extension/scripts/diff-ast.js#L5), [`vscode-extension/src/diffAst.js:6`](../../../vscode-extension/src/diffAst.js#L6), [`vscode-extension/src/diffAst.js:15`](../../../vscode-extension/src/diffAst.js#L15)). Ele é exposto como script integrado no catálogo da extensão ([`vscode-extension/src/catalog.js:72`](../../../vscode-extension/src/catalog.js#L72)).

## Documentação gerada e documentação manual

O manifesto lista `index.md`, `changes.md` e arquivos sob `modules/` como saídas geradas; os guias desta pasta não estão nessa lista ([`docs/architecture/.agentorchestra-docs-manifest.json:2`](../.agentorchestra-docs-manifest.json#L2)). O publicador copia a documentação anterior e substitui apenas os arquivos registrados no manifesto ([`vscode-extension/src/projectDocs.js:269`](../../../vscode-extension/src/projectDocs.js#L269), [`vscode-extension/src/projectDocs.js:288`](../../../vscode-extension/src/projectDocs.js#L288)). Assim, as notas manuais de `guides/` podem conviver com a próxima geração. **Não verificado:** uma regeneração executada após esta edição; a conclusão decorre do código e do manifesto atual.
